# the-refusal-names-the-clarification

The ring that carries a forwarded clarification contradicts itself, and it stopped the
Saibill forge's lieutenant on the request it was attached to.

This is what arrives in a pane when the operator forwards a clarification an agent is
blocked on:

  Answer with: pack_dashboard_request.sh answer <id> ./tmp/answer.txt (a reply only in this
  pane reaches nobody). This one is a clarification an agent is blocked on, and the answer
  is the operator's to give: read the question, ground it in the project's state, then reply
  with what you would answer and why. Do not answer it unless the operator says to.

The first sentence asks for an answer; the last clause forbids one. Both are about different
acts and use one word for both: the reply that has to travel through the dashboard so the
operator can see it, and the decision that unblocks the agent, which is the operator's. The
operator's reading of the fix: say "do not answer the clarification request" rather than "do
not answer", so the refusal names what it refuses.

The same words are in the dashboard - `pack_web.bb`'s `answer-reminder`, which builds
`chat-wake` - so the two change together and stay identical. This card is the kit's half:
the doorbell's clause, its self-check constant, and the feature and tests that pin the
refusal verbatim. The layer's copy is the lieutenant's own edit in its own repository.

The acceptance worth pinning is the one the feature already has, with the words changed: a
ring for a clarification the bridge wrote says the answer is the operator's to give, and not
to answer the clarification request unless the operator says to.
